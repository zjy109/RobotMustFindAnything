RoFA-SemEval · 数据集与脚本方案 v5

面向《指标 4.2 环境语义表达准确率》的本地真实采集方案：采集 / 标注 / 发布 三阶段解耦
设备：Intel RealSense D435（仅 RGB-D，无底盘 / 无 SLAM） 位姿来源：Dummy（单位阵） 类别：采集时由采集员动态输入 数据集形态：单一全集（无 train/test 划分）
目录： 1. 流程总览 2. 环境配置 (Conda) 3. 角色分工 4. 关键决策（v5） 5. 位姿讨论 6. 目录结构 7. 文件格式 8. 标注流程 9. 脚本规划 10. 与现有代码的衔接 11. 待确认事项

1. 流程总览（三阶段彻底解耦）

阶段 1 · 采集

谁：采集员
做：输入物品名 + 按空格拍照
不接触：mask、点云、AABB、相机参数
产出：raw_capture/pending/
→

阶段 2 · 标注

谁：标注员
做：画 mask + 决定保留/删除
不接触：硬件、相机内参
产出：标注+清洗后的 raw_capture/
→

阶段 3 · 发布

谁：数据负责人
做：完整性校验 + 拷贝整理
不接触：样本本身的内容判断
产出：dataset/ 单一全集
核心约定：
  • 每个阶段的人只负责自己那一段，互不依赖；
  • 采集员可以一次拍上百条然后离场，不需要等标注员；
  • 标注员可以在任意时间打开 raw 池开始标注，不需要采集员在场；
  • 最终发布的 只有一个数据集，无 train/test 划分，所有有效样本都是评测样本。

2. 环境配置（Conda）

推荐做法：用 conda 创建一个独立环境 rofa-data，所有依赖装在里面，避免污染系统 Python，也方便随时清空重装。

conda create -n rofa-data python=3.10 -y
conda activate rofa-data

2.4 平台说明

  • RealSense 驱动：pyrealsense2 在 macOS 上没有官方 wheel，需要在 Linux/Windows 机器上跑采集；本仓库已有 D435 工程默认部署在 Linux。
  • open3d：Apple Silicon (M1/M2/M3) 的支持有时滞后；如果装失败，annotate 脚本会自动降级到 numpy 兜底（仅做 5σ 过滤），仍可生成 mask + AABB，只是去噪效果略弱。
  • matplotlib 缺失：跳过 3D 立体图，2D 投影图与 AABB 数值仍正常输出。
  • pypinyin 缺失：中文类别名会回退到 zh_<utf8 hex> 形式作为目录名（仍可跑通流程，但目录名不可读）。

2.5 卸载 / 重置

conda deactivate
conda remove -n rofa-data --all -y
项目里已有 conda 环境 rofa：本仓库 README.md 的"环境配置"是为整个 rofa（含 SAM3 + RynnBrain + ROS2）准备的重型环境。 本数据集脚本不需要 SAM/LLM/ROS，因此推荐新建一个轻量的 rofa-data，避免污染原 rofa 环境。 若你确实要复用原 rofa，只需 conda activate rofa 后 pip install -r scripts/requirements.txt 补齐即可。

4. 关键决策（v5 对齐版）

三阶段解耦 单一全集 扁平按类别 位姿=I (dummy) 人工画轮廓+填充 类别动态输入 采集端零约束 标注员可删减
维度 v4 v5 最终
采集 vs 标注 合并为 1 个流程，由"标注员"在采完之后立即标 分离为 2 个独立脚本，采集员只拍照、不画 mask
是否分 train/test 有 splits/test.json 不分。仅一个 samples.json 全集索引
样本删减权 校验脚本自动剔除（仅文件级） 标注员可主动删除任何样本（移到 discarded），发布脚本只做完整性兜底
raw 池 / 数据集 合并在一起 分离：raw_capture/（中间产物）vs dataset/（最终发布）
1000 / 20 / 25-75 大纲建议刻度，仅作报告 同 v4，仅在 dataset_report.json 中对照展示

5. 关于"用 dummy 位姿是否影响 benchmark"

结论：不影响 IoU3D 数值，但需在数据集说明里声明坐标系约定。

5.1 数学推导

  • mask + depth + 内参反投影得到的是 相机坐标系下的点云 P_cam。
  • 世界系点云 P_world = R · P_cam + t，其中 (R, t) = T_world_camera。
  • 当 T_world_camera = I 时，P_world ≡ P_cam。
  • IoU3D = 体积比，对刚体变换 (R, t) 保不变。GT 与预测都用同一约定（pose=I），AABB IoU 数值不受影响。
✅ 安全前提：预测端（SearchEngine._mask_to_world_points）也使用 pose=I。本工程已经支持：在 pose.txt 写单位阵，MainOnRobot 直接吃。

5.2 这种简化的代价

  • ❌ 失去"多帧融合 / 跨帧检索"能力（每条样本独立，等价于"单帧定位"）。
  • ❌ 失去大纲 P30 中"语义地图构建模型"在本指标下的实际贡献。
  • ✅ 但 IoU3D ≥ τ → Accτ 的核心评测不受影响。

关键设计：
  • raw_capture/ 是采集 + 标注的"工作台"，整个项目只属于内部使用。结构包含 pending / annotated / discarded 三个子目录代表样本的三种状态。
  • dataset/ 才是对外发布的"成品"。它由 finalize 脚本从 raw_capture/annotated/ 复制而来，结构干净、自包含、可单独打包分发。
  • 样本在三种状态间转移 = 移动目录（pending → annotated 或 pending → discarded），原子且可追溯。

6.2 命名规则

  • 类别目录：英文 slug（中文输入自动转拼音），同时在 classes.json 保留中文名与所有 alias。
  • sample_id：{class}_{4位序号}，如 bottle_0023。同类内序号递增、跨类不复用。
  • 样本在 pending / annotated / discarded 间移动时 sample_id 不变，便于追溯。

8. 标注员工作流（连通域边界 + 自动填充 + 删减权）

  1. 启动 annotate_sample.py，自动跳到下一个 raw_capture/pending/ 中未标注样本。
  2. 窗口左侧显示 rgb.jpg，右侧显示深度伪彩色图（辅助判断目标可视性）。
  3. 标注员用鼠标 左键 沿目标轮廓依次点击，画一圈 闭合多边形。
  4. 按 空格 / 右键：脚本调用 cv2.fillPoly 把多边形内部填充为前景，得到二值 mask.png。
  5. 脚本立即完成下游全自动处理：
    • 读 depth + intrinsics → 反投影 mask 区域 → 相机系点云；
    • 深度范围过滤（0.2~5.0 m）+ 统计离群点（SOR）+ DBSCAN 选最大连通簇；
    • 计算 AABB → 写 aabb.json + points.ply；
    • 渲染 viz_mask.png 与 viz_aabb.png（复用 SearchEngine._save_aabb_2d_overlay）；
    • 写 sample.json。
  6. 标注员决策：
    键含义样本去向
    y接受 GT整目录从 pending/ 移到 annotated/
    n重做（mask 不满意）清空 mask，回到第 3 步
    d删除样本（采集质量差 / 目标不可辨）整目录从 pending/ 移到 discarded/，附 discard_reason.txt
    s跳过（暂时不处理）留在 pending/
    q退出—
关键权限：标注员有单方面删除样本的权力（d 键）。删除不会真的丢文件，而是移动到 discarded/ 子目录并附原因，便于事后追溯或回收。

9.1 阶段 1 · capture_sample.py

项设计
输入参数--raw-root raw 池根目录（默认 ./RoFA-SemEval/raw_capture）
--operator 采集员标识（可选）
启动用 pyrealsense2 启动 D435：彩色 640×480@30 + 深度 640×480@30，rs.align(rs.stream.color) 把深度对齐到彩色
首帧读 rs.video_stream_profile.get_intrinsics() + depth_sensor.get_depth_scale()
类别管理启动后终端提示输入物品名（中英文均可）。脚本归一化输入并查 classes.json：命中 alias→复用；未命中→显示模糊匹配候选→用户选 "复用 / 新建"
主循环实时窗口显示 RGB + 深度伪彩色 + 状态栏（当前类、当前类已采数、所有类累计、下一序号）。仅展示事实统计，无目标进度
触发抓拍空格 = 抓拍：自动确定下一个 bottle_0007，建目录于 raw_capture/pending/bottle/，落盘 rgb.jpg / depth.png / intrinsics.json / pose.txt(=I) / capture_meta.json
切换类别n 键 = 切换或新建类别（再次走类别输入流程）
有效性即时检查抓拍前先检查：① 深度有效像素占比 ≥ 50%；② 中心区域有非零深度。不达标拒绝抓拍并提示
退出q 退出，打印本次采集统计
不做的事❌ 不画 mask；❌ 不算 AABB；❌ 不强制类别上限；❌ 不强制总数
采集时序伪代码 
pipeline = rs.pipeline()
config = rs.config()
config.enable_stream(rs.stream.color, 640, 480, rs.format.bgr8, 30)
config.enable_stream(rs.stream.depth, 640, 480, rs.format.z16, 30)
profile = pipeline.start(config)
align = rs.align(rs.stream.color)
intr = profile.get_stream(rs.stream.color).as_video_stream_profile().get_intrinsics()
depth_scale = profile.get_device().first_depth_sensor().get_depth_scale()

current_class = resolve_class(input("当前类别："), classes_json)

while True:
    frames = align.process(pipeline.wait_for_frames())
    color = np.asanyarray(frames.get_color_frame().get_data())
    depth = np.asanyarray(frames.get_depth_frame().get_data())  # uint16 mm
    show(color, depth, current_class)
    key = cv2.waitKey(1) & 0xFF
    if key == ord(' '):
        if not depth_quality_ok(depth):
            print("深度质量不达标，重拍")
            continue
        sample_dir = next_pending_dir(raw_root, current_class["name"])
        save_rgb(sample_dir / 'rgb.jpg', color)
        save_depth_uint16(sample_dir / 'depth.png', depth)
        save_intrinsics(sample_dir / 'intrinsics.json', intr, depth_scale)
        save_pose_identity(sample_dir / 'pose.txt')
        save_capture_meta(sample_dir / 'capture_meta.json', current_class, operator)
        bump_captured_count(classes_json, current_class)
    elif key == ord('n'):
        current_class = resolve_class(input("切换类别："), classes_json)
    elif key == ord('q'):
        break

9.2 阶段 2 · annotate_sample.py

项设计
输入参数--raw-root raw 池根目录
--annotator 标注员标识
--class 仅标注指定类别（可选，便于分工）

去噪① depth ∈ [0.2, 5.0] m；② open3d.PointCloud.remove_statistical_outlier(nb=30, std=2.0)；③ cluster_dbscan(eps=0.03, min_points=50) 取最大簇

可视化复用 _save_aabb_2d_overlay + _save_aabb_3d_plot

失败兜底点云数 < 阈值 / AABB extent 任一维 ≤ 0：提示重做或建议删除
